Table detection clusters aligned text into real Word tables, including form-style label/value grids (invoice headers, ID fields) even when row heights vary slightly. OCR fallback (Tesseract.js) kicks in automatically on pages with little or no extractable text — it's slower and won't capture bold/italic, since that information doesn't survive OCR. One honest limit: the outer box/border lines you see in many PDFs (invoice frames, ruled boxes) are vector graphics, not text — only content recognized as a table gets a border in the output, so a converted document will have the right text and structure but won't visually box things the PDF didn't express as a genuine table.

Font matching reads which fonts the .docx specifies and applies the closest matching web font family per element (serif for Georgia/Cambria/Times, monospace for Consolas/Courier, etc). This is font matching, not literal embedded-font extraction — real font files embedded in a .docx are rare and stored in an obfuscated binary format that isn't reliably recoverable in-browser, so the closest visual match is used instead.
Built with pdf.js, mammoth.js, JSZip, jsPDF, html2canvas & Tesseract.js — all processing is local to this page.
